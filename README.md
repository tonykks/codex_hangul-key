# 한글 글쇠 연습

두벌식 글쇠 위치와 기본 손가락 사용법을 익히는 연습 프로그램입니다. 속도·박자·손가락 사용 여부는 채점하지 않습니다.

## 실행

로그인 없이도 같은 글쇠 연습과 TXT 저장을 사용할 수 있습니다. Google 계정으로 로그인하면 별칭을 등록하고 Firestore에 기록을 누적합니다. 로그인·온라인 기록의 로컬 테스트에는 웹 주소를 사용합니다. HTML, CSS, JavaScript 파일과 music 폴더를 함께 보관하세요.

개발용 웹 주소로 실행하려면 프로젝트 폴더에서 `npm start` 또는 `node serve.mjs`을 실행한 뒤 http://localhost:8765 에 접속합니다. 이 명령은 개발자 PC에 Node.js가 있을 때 사용합니다. 학생이 공개 웹 주소로 접속할 때는 필요 없습니다.

## Firebase 연결

1. Firebase Console에서 프로젝트의 웹 앱을 등록합니다.
2. 프로젝트 설정 → 일반 → 내 앱 → 웹 앱 → SDK 설정 및 구성의 `firebaseConfig`를 `firebase-config.js`에 넣습니다. 웹 앱 구성만 사용하며 서비스 계정 비공개 키는 넣지 않습니다.
3. Authentication → 로그인 방법에서 Google을 활성화하고 지원 이메일을 설정합니다. 앱은 Google 로그인만 제공합니다(Google Workspace 계정도 포함).
4. Authentication → 설정 → 승인된 도메인에 로컬 테스트용 `localhost`를 추가합니다. 새 프로젝트에는 localhost가 기본 등록되지 않을 수 있습니다. 공개 주소의 도메인 `tonykks.github.io`도 승인된 도메인에 등록합니다.
5. `npm run build`로 번들을 갱신하고 http://localhost:8765 에 접속합니다. 설정 누락·잘못된 도메인·팝업 차단 시 로그인 오류를 안내하며 비로그인 연습은 계속 사용할 수 있습니다.

로그인은 Firebase SDK의 Google 팝업을 사용합니다. Firebase SDK(13.1.0)는 Google CDN에서 불러오므로 인터넷 연결이 필요합니다. 공용 PC를 고려해 로그인 유지 범위는 현재 브라우저 세션입니다. 작업 후 Logout을 누릅니다.

공식 문서: [Google 로그인](https://firebase.google.com/docs/auth/web/google-signin), [CDN SDK 연결](https://firebase.google.com/docs/web/alt-setup), [localhost 승인 도메인 안내](https://firebase.google.com/docs/auth/faq-and-troubleshooting).

## 사용

1. 안내 언어와 세트, 글쇠를 선택합니다. 기록을 누적하려면 **Login**으로 Google 계정에 로그인하고 첫 방문 시 별칭을 등록합니다. 별칭 중복은 허용하며 `별칭(UID 마지막 4자리)`로 표시합니다. 실제 저장 키는 전체 UID입니다.
2. 안내를 읽고 **연습 시작**을 누릅니다. 한/영 상태와 관계없이 물리 글쇠를 두벌식 자모로 기록합니다.
3. 실제 키보드에서 같은 글쇠를 천천히 반복합니다. 오답도 1회이며, 20회마다 다음 줄로 이동합니다.
4. Shift 세트에서는 반대쪽 Shift를 매번 눌렀다 놓습니다. 프로그램은 입력 순간의 Shift 방향을 검사하며 실제 손가락·복귀 동작은 감지하지 않습니다.
5. 원하는 음악을 선택하고 오디오의 재생 버튼을 누릅니다. 음악은 반복 재생합니다.
6. **TXT 저장 · 보기**는 현재 기록을 다운로드하고 보여줍니다. 연습을 종료하지 않으며, 기록 창을 닫고 시작 버튼으로 이어서 연습할 수 있습니다.
7. **다시 시작**은 확인 후 현재 화면의 입력 기록과 시작 시각을 초기화합니다. 로그인 상태에서는 초기화 전 입력을 Firestore에 저장하고 이미 쌓인 누적 기록을 유지합니다. 언어와 Shift 호환 설정도 유지합니다.
8. **Logout**은 Firestore 저장을 기다린 뒤 연습 종료 시각을 기록하고 로그아웃합니다. TXT를 자동 다운로드하지 않습니다. 필요한 TXT는 Logout 전에 저장하세요. 저장 실패 시 로그아웃을 중단하므로 연결을 확인한 뒤 다시 눌러 주세요.
9. **랭킹**은 로그인 학생의 누적 시간 상위 5명을 표시합니다. 별칭을 누르면 접속 시각·최초 입력·로그아웃 시각·입력/오타 수·점수를 볼 수 있습니다. 점수는 전체 정답 수 − 전체 오타 수이며 최소 0점입니다. 시간 순으로 정렬하며 점수로 정렬하지 않습니다.

글쇠·세트를 바꾸거나 창을 벗어나면 입력을 잠시 멈춥니다. 시작 버튼으로 재개하세요. 잘못 입력한 기록은 지울 수 없습니다.

현재 화면의 기록은 브라우저 Local Storage에도 저장합니다. 비로그인 기록은 서버나 로그인 계정으로 자동 합치지 않습니다. 로그인 학생의 별칭·접속별 통계·실제 입력 결과는 Firestore에 저장하며 과거 기록은 랭킹/상세에서 조회합니다. 새 기기에서 현재 입력 칸을 이어 쓰는 기능은 제공하지 않습니다. 기존 로그인 버전의 테스트 기록은 별도 로컬 보관본으로 남기고 새 Firestore 방문에 자동 합산하지 않습니다.

## Firestore 기록과 관리자

- 데이터베이스: `(default)`, Standard, `asia-northeast3`(서울).
- `students/{uid}`: 별칭과 UID 뒤 4자리. `students/{uid}/runs/{runId}/chunks`에 실제 입력 문자를 1,000개 이하의 문서로 나누어 저장합니다. 전체 연습 횟수 제한은 없습니다.
- `visits/{visitId}`: 로그인 접속, 최초 입력, 마지막 저장, 로그아웃 시각 및 누적 입력/오타/시간/점수입니다. 새로고침은 같은 접속을 이어가고, 로그아웃 후 재로그인은 새 접속입니다.
- 첫 입력과 약 30초 간격, 랭킹 조회, 초기화, 로그아웃 시 저장합니다. 재시도는 같은 runId의 차이만 반영해 중복 누적을 방지합니다.
- 시간은 최초 입력부터 로그아웃까지의 경과 시간입니다. 로그인 후 입력 전 대기는 제외하고, 최초 입력 뒤 휴식·안내 읽기 시간은 포함합니다. 로그아웃 전에는 마지막 저장 시각 기준으로 랭킹에 반영합니다.
- 브라우저/PC를 강제로 닫으면 정확한 로그아웃 시각을 알 수 없어 마지막 저장분까지만 남을 수 있습니다. 마칠 때 Logout을 사용하세요. 방문에 로그아웃 시각이 없으면 상세에는 `—`로 표시합니다.
- 현재 소유자의 Firebase UID를 firebase-config.js의 adminUid와 firestore.rules에 지정했습니다. 관리자만 학생 전체 목록을 볼 수 있고, 관리자 기록은 학생 랭킹과 합산에서 제외합니다. 관리자 테스트 기록은 관리자 화면의 별도 버튼으로 조회합니다.
- 일반 로그인 사용자는 랭킹용 접속 통계를 조회할 수 있습니다. 전체 학생 명부와 다른 학생의 실제 입력 문자 문서는 관리자만 읽을 수 있고, 자신의 데이터만 쓸 수 있습니다. 클라이언트가 임의로 관리자 필드를 등록할 수 없습니다.
- Firestore 콘솔의 규칙 탭에 firestore.rules를 게시합니다. 이번 작업에서는 실제 게시를 완료했습니다. 이후 관리자 UID를 바꾸면 코드와 규칙을 함께 갱신해야 합니다.
- 랭킹은 현재 교실 규모에 맞춰 비관리자 방문 통계를 읽어 합산합니다. 일반 학생 계정으로 별칭 등록·반복 접속·랭킹 상세를 추가 검수하세요.

## 음악 추가

현재 제공된 `music/track1.mp3` ~ `music/track4.mp3`를 사용합니다. 음악을 추가하려면 파일을 `music` 폴더에 넣고 `practice-data.js`의 `tracks`에 `{name:'표시 이름',src:'music/파일명.mp3'}`를 추가한 다음 `npm run build`를 실행합니다. 로컬 상대 경로를 사용하세요.

2026-10-31 소유자 승인으로 Track 1~4의 MP3를 공개 배포에 포함합니다. 이 네 파일 이외의 음악 파일은 기본적으로 Git에서 제외합니다.

## 개발·검증

교사 PC에서 Shift 신호를 비교하려면 [Shift 신호 확인](keyboard-check.html)을 Chrome에서 엽니다. 연습의 정오답 판정을 거치지 않고 좌우 Shift 단독 입력과 Shift+E 입력의 원본 이벤트를 비교합니다. 결과는 저장·전송하지 않습니다.

오른쪽 Shift가 좌우 위치 정보 없이 전달되는 PC에서는 9·10세트의 **Shift 설정**을 누르고 왼쪽 Shift를 누른 뒤 놓고, 다음 안내에서 오른쪽 Shift를 누른 뒤 놓습니다. 설정 후 연습 시작을 누릅니다. 이 브라우저에 설정이 저장되며 연습 기록은 바뀌지 않습니다. 정상 PC는 설정 없이 사용할 수 있습니다. 키보드 또는 입력 환경이 바뀌면 다시 설정하세요. 왼쪽 Shift도 위치를 구분할 수 없는 경우에는 이 호환 설정을 적용하지 않습니다.

개발용 패키지 설치는 필요 없습니다. 실행 시 Firebase SDK를 Google CDN에서 불러옵니다. Node.js가 설치된 환경에서:

```text
npm run build
npm test
```

소스는 practice-data.js, core.js, cloud-model.js, translations.js, firebase-config.js, auth.js, cloud.js, app.js입니다. 변경 후 `node build.mjs`로 브라우저용 app.bundle.js를 갱신합니다. 번들을 함께 배포해야 합니다. 번역은 translations.js에 언어별로 있으며, 미얀마어·베트남어의 자연스러움은 원어민 검수가 필요합니다.

검증 범위와 미완료 사항은 로컬 전용 `TEST_RESULTS.md`에 기록합니다. 현재 자동 테스트 42개가 통과하며, 사용자 PC의 특수 Shift 신호는 제공된 로그를 재현해 검증했습니다. 실제 물리 키보드의 최종 확인은 별도입니다.


## 공개 배포와 파일 보호

- 사이트: https://tonykks.github.io/codex_hangul-key/
- 저장소: https://github.com/tonykks/codex_hangul-key
- main에 push하면 GitHub Actions에서 파일 검사 → 자동 테스트 → 빌드 → GitHub Pages 배포를 실행합니다. 저장소 Settings → Pages의 Source는 GitHub Actions입니다.
- `npm run build:site`는 `dist/`에 HTML/CSS/번들/키보드 진단 화면과 승인된 MP3 4개, `.nojekyll`만 복사합니다. 소스 저장소 전체를 웹 루트로 공개하지 않습니다.
- `.gitignore`는 개인 TXT 기록, 테스트 스크린샷·로그, 내부 강연자료, 환경변수, 서비스 계정 키, DB와 임시 산출물을 제외합니다.
- `release-check.mjs`는 Git에 등록할 수 있는 파일을 명시적으로 제한하고 비공개 키·주요 토큰 형태를 검사합니다. 검사 규칙은 알려진 패턴에 한정되므로 새 파일을 공개할 때는 내용을 함께 검토하세요.
- 로컬 commit 전 검사를 활성화하려면 `git config core.hooksPath .githooks`를 실행합니다. GitHub 배포 작업에서도 같은 검사를 필수로 실행합니다.
- `firebase-config.js`의 Firebase 웹 앱 구성(apiKey 등)은 브라우저 실행에 필요한 공개 설정입니다. Firebase 서비스 계정 비공개 키나 관리 API 토큰이 아닙니다. 데이터 접근 권한은 Authentication과 Firestore 규칙으로 제한합니다.
- 파일 실행/localhost/공개 사이트는 서로 다른 브라우저 저장소를 사용합니다. Shift 설정은 각 주소에서 적용해야 합니다. 설정 2단계에서 멈추는 기존 키보드는 **Shift 설정 → 이전에 성공한 오른쪽 Shift 설정 적용**을 사용합니다.
